# T060 — Phase 5 capability/context architecture gate

Depends on: Phase 4 complete; T051 Final Audit approved. Implementation Model: STRONG; Review: Planning Strong Review; planning only.

## Objective
Freeze the smallest Phase 5 contract for bounded capabilities and sanitized context without reopening ADR-006.

## Decisions to freeze
Use one `Capability` concept, with explicit typed metadata and an async dispatch contract; do not create separate Skill/Tool registries. A capability receives validated `PlanStep` input plus a bounded `ContextEnvelope` and returns existing `ExecutionResult` shape or normalized `RuntimeFailure`. Initial capabilities remain deterministic, read-only, in-process, and side-effect-free. Dispatch is an explicit dependency mapping supplied to the Executor; no dynamic loading or marketplace. Context contains only task input, current step, and explicitly selected sanitized sources with provenance and size bounds. Authority, sessions, repositories, secrets, checkpoint objects, and raw exceptions never enter AgentState/checkpoints/logs.

## Acceptance criteria
ADR-007 defines capability input/output, bounded output, sanitization, failure mapping, retry/replan interaction, checkpoint attempt semantics, tenant check location, and replay limitation. It explicitly defers credential-bearing and real-effect capabilities, persistent Skill/Tool/Context/Invocation tables, public APIs, HITL, and generic memory/knowledge infrastructure.

## Strong Review focus
Check that every new field reuses ADR-006 contracts, no authority crosses the AgentState boundary, and the first slice is safe under repeated/concurrent resume.
