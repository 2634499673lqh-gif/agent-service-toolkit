# T021 — Organization model and migration

Implementation Model: STANDARD  
Review Model: STRONG_REVIEW_REQUIRED

Implement only the Organization schema approved by T020. Do not implement login, token issuance, current-user dependencies, RBAC checks, User schema, or public registration.

## Depends on

T020 accepted ADR.

## Scope

Exact approved ORM model, repository boundary, migration revision, UTC timestamps, active/deletion policy, indexes/constraints, and focused migration/model tests. Use the approved transaction/session factory; do not put ORM sessions in LangGraph state. Keep LangGraph tables outside the revision.

## Acceptance

- Fresh database applies LangGraph setup and TaskPilot migration in the approved order.
- Organization constraints, ID type, lifecycle and rollback behavior match T020.
- Tenant filters are explicit in repository APIs; no route handler performs raw DB access.
- SQLite support or explicit non-support is tested and documented.
- Cross-tenant data is never returned by organization-scoped repository methods.

## Required files/tests

Use only paths named by the T020 decision plus focused model/migration tests and progress/docs files it authorizes. Run the focused migration/database tests, then shared tests required by the repository. Strong review must inspect SQL and downgrade behavior.

Migration verification must cover fresh database upgrade, existing database upgrade, revision metadata/version, LangGraph setup coexistence, and the T020 downgrade policy; an ORM model test alone is insufficient. Full pytest is a gate after T021/T022.
