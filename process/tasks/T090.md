Depends on: Phase 6 complete. Review: Planning Strong Review.

## Objective

Accept ADR-009 as the executable Phase 7 observability boundary. The business
database remains authoritative for Task, TaskRun, tenant, lifecycle, approval,
and outcome; telemetry is observation only.

## Scope

Freeze the T091–T097 persistence, correlation, normalization, usage, cost, and
tenant-safe query contracts in ADR-009. Freeze the DAG
T090 → (T091, T092) → T093 → (T094, T095) → T096 → T097 → T098.

## Explicit non-scope

No runtime code, migration, external tracing deployment, analytics/event bus,
worker, billing, UI, evaluation, duplicated tenant authority, or lifecycle
change.

## Acceptance criteria

ADR-009 is accepted only when a fresh implementer can execute T091–T097 without
choosing persistence ownership, tenant joins, identity keys, bounds, status
semantics, redaction boundaries, or authentication behavior at implementation
time.

## Evidence

Review the exact field/constraint tables and negative cases in ADR-009. Any
conflict with a frozen Task, TaskRun, approval, checkpoint, or tenant contract
stops the phase for a new ADR.

## Documentation and checks

Update only the relevant planning and observability documentation. Run
git diff --check and focused consistency searches; no runtime or PostgreSQL
execution is part of this planning fix.
