# T140 — Live Runtime Reliability and Observability

**Model:** STRONG/STANDARD  **Review:** Strong Review  **Depends:** T139

**Scope/files:** `src/runtime/{graph,planner,failure,observability,state}.py`,
`src/geochange/{runtime_caps,stac,verifier}.py`,
`src/persistence/models.py:_validate_result_metadata`,
`src/service/task_runtime.py:TaskRuntimeService._finish` and initialization/
finalization paths, `src/schema/task_run_api.py`, `src/taskpilot_ui.py`, and
focused runtime/PostgreSQL/Product tests. Persist the exact allowlisted
`result_metadata.stage_status` object with fixed keys `planner`, `execution`,
`verifier` and statuses `not_started|running|passed|failed|not_run`.
Terminal metadata uses `not_run` for skipped downstream stages; active `running`
is exposed only by existing TaskRun lifecycle and AgentRun/ToolCall observations.
Explanation is part of execution, not a fourth stage. Reuse existing
AgentRun/ToolCall provider metadata and sanitized error fields for provider,
model, normalized code/class, and bounded duration; do not create a new trace
subsystem.

**Acceptance/evidence:** planner failure yields planner=`failed`, execution and
verifier=`not_run`; capability failure yields planner=`passed`, execution=`failed`,
verifier=`not_run`; verifier rejection yields planner/execution=`passed`,
verifier=`failed`; success yields all three `passed`. Active stage transitions
are observable without writing `running` into terminal metadata. The existing
allowlist and byte bound reject malformed stage maps. Provider/network,
malformed response, no imagery, explicit-quality violation, and default-quality
violation follow ADR-013; budgets remain bounded; no secrets, bodies, prompts,
or tracebacks persist. PostgreSQL and lifecycle regressions pass.

**Stop:** stop for a new table, lifecycle enum, worker, or cross-system
transaction requirement. **Deferred:** distributed workers and exactly-once.
