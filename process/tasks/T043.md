# T043 — Executor interface

Depends on: T042. Implementation Model: STRONG/STANDARD; Review: Strong Review.

## Objective and scope

Define the narrow typed executor interface for one PlanStep and its deterministic result/error contract. Dependency injection is allowed; no generic tool/skill registry, provider adapter, shell, filesystem, network, credentials, approval, lease, or external effect.

## Acceptance / security / transaction / tests

Interface inputs/outputs and failure behavior are explicit, side-effect-free, and compatible with AgentState. Authorization never comes from PlanStep or executor output. Add contract and serialization tests, including failure classification inputs. No long-lived DB transaction. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: executor interface. Required tests cover contract, serialization, and failure shape; PostgreSQL/integration evidence is not required. Strong Review is required.

## Frozen contract

`execute(step: PlanStep, task_input: {title: str, description: str | null})`
returns `ExecutionResult(step_position: int, success: bool, output: string <=
2000 chars | null, error_code: string <= 64 chars | null, error_message: string
<= 500 chars | null)`. All strings are bounded and sanitized. Success requires
output and no error fields. Failure requires a normalized error code, may
contain a sanitized message, and never contains a raw exception or
authorization context.
