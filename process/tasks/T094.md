# T094 — Latency/status/error normalization

Depends on: T093. Review: Strong Review.

## Objective

Normalize bounded observational timing, status, error, retry, and replan
evidence without creating a second Task/TaskRun state machine.

## Required contract

- Use UTC-aware ISO 8601 at API boundaries and PostgreSQL timestamptz in
  storage.
- Represent duration as nullable non-negative integer milliseconds bounded to
  0..86,400,000; missing timing stays NULL, never zero.
- Use only the AgentRun/ToolCall observational statuses in ADR-009. Existing
  TaskRun lifecycle values remain authoritative.
- Preserve existing runtime RETRY, REPLAN, and TERMINAL classifications; use
  UNKNOWN only when a source cannot classify an error. Error codes are at most
  64 characters and sanitized messages at most 500.
- A retry is a new AgentRun row with incremented retry_count in the same
  replan. A replan increments replan_count and starts at position 0. Previous
  rows remain immutable evidence.

## Acceptance and negative evidence

Deterministic tests cover malformed timestamps, finish-before-start, oversized
errors, missing timing, unknown classification, retry visibility, replan
visibility, and prove no TaskRun lifecycle state is changed.

## Documentation and checks

Update observability documentation and run focused tests, static checks, and
git diff --check during implementation.
