# T097 — Tenant-safe trace query API

Depends on: T091–T096. Review: Strong Review.

## Objective

Return a bounded, ordered, sanitized execution timeline for one visible
TaskRun.

## Required contract

The planned route is
GET /api/v1/tasks/{task_id}/runs/{run_id}/trace. limit defaults to 100 and is
capped at 500; a visible run with no rows returns 200 [].

Every SQL query constrains the requested Task and TaskRun and applies
Task.organization_id = principal.organization_id before projection or
pagination, then joins AgentRun and ToolCall through their foreign keys. A
global fetch followed by Python tenant comparison is forbidden.

Authentication/visibility is the existing contract: invalid or absent
credentials are generic 401 with WWW-Authenticate: Bearer; nonexistent or
cross-tenant resources are 404 Not Found; any active member may read a visible
in-tenant run, matching TaskRun inspection, so this read adds no role gate or
new 403. Any future role-gated operation must use the existing 403 Forbidden
helper and retain cross-tenant 404.

The response is an allowlisted projection of correlation IDs, server-selected
names, status, UTC timing, duration, normalized errors, usage, estimate result,
and bounded sanitized metadata. It excludes checkpoints, prompts, context,
credentials, authorization objects, raw provider responses, and unbounded
payloads. Apply the existing recursive redaction helper again at the response
boundary.

Stable order is started_at ASC, event kind (AgentRun before ToolCall),
agent_run_id ASC, call_index ASC (null for AgentRun), and event ID ASC. Do not
collapse earlier failed attempts: failure, retry, and replan are reconstructed
from each AgentRun's coordinates/error and its ToolCall children.

## Acceptance and negative evidence

PostgreSQL tests prove SQL tenant scoping, 401/404 behavior, empty traces,
stable tie ordering, limit bounds, response redaction, and reconstruction of
failure/retry/replan. T097 owns response-redaction tests; T092 owns persisted
payload redaction tests.

## Documentation and checks

Update API/observability documentation and run focused tests, static checks,
and git diff --check during implementation.
