# T084 — Resume and idempotent approved action

Depends on: T083.

Resume only the tenant-validated run and exact pending action after approval.
Reject stale, cancelled, rejected, or mismatched approvals. Execute one
deterministic mock effect behind an atomic action-key claim/record; duplicate
HTTP/simulated-worker delivery returns the recorded outcome when completed.
ADR-008 B3 is authoritative: the approved-action service owns a short transaction
and NOWAIT Task -> Run -> Approval locks; busy returns conflict. B2's tuple is
the only key. AVAILABLE is claimed by the transaction lock (no durable CLAIMED
state); COMPLETED returns outcome; FAILED returns failure without retry. The
mock effect is solely the Approval outcome write, atomic with its terminal
action_state. Rollback leaves no effect; replay after commit reads the outcome.
Cancellation/terminal state is checked under the shared T035 Task lock before
any action and always prevents later resume. No lease/recovery framework.
Do not claim exactly-once behavior for real external systems.

Evidence: approve/resume success, reject/no-effect, cancellation race,
duplicate delivery, concurrent claim, terminal-state protection, and replay
tests.
