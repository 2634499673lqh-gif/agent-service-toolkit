# T042 — Planner node

Depends on: T041. Implementation Model: STANDARD; Review: Strong Review.

## Objective and scope

Implement the bounded planner node using the T041 schema and a mockable model boundary. It must produce a structurally validated Plan and apply the documented one-shot repair-or-terminal-failure rule. It must not grant authorization or introduce generic prompt/tool registries, provider credentials, or HTTP routes.

## Acceptance / security / transaction / tests

Deterministic tests cover valid output, invalid output, bounded repair, terminal invalid output, and secret-safe errors. AgentState remains serializable and contains no session/ORM/principal. Runtime calls do not hold a PostgreSQL transaction; lifecycle remains T035-owned. Update task/docs/progress; no Codex commit/push.

## Governance

Affected layer: planner node/runtime boundary. Tenant authority remains server-derived. Required tests are mocked deterministic unit tests; no PostgreSQL evidence unless an existing integration fixture is reused. Strong Review is required.

## Frozen contract

Input is sanitized `task_input` plus the planner context defined by ADR-006;
output is a validated `Plan`. The node gets exactly one repair attempt after
invalid structured output. Repair receives only the validation failure and
the original planner output/context needed for correction. A second invalid
result becomes terminal normalized `planner_output_invalid`; it does not enter
the replan budget. Repair is not a replan.
