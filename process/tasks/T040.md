# T040 — Phase 4 runtime architecture / AgentState contract

Implementation Model: STRONG; Review: Planning Strong Review; Status: APPROVED / COMPLETE

## Objective

Freeze ADR-006 as the implementation authority for the smallest bounded Planner → Executor → Verifier runtime with retry, replan, and checkpoint/resume. Planning only; no production code, ORM, migration, API, dependency, commit, or push.

## Authoritative dependencies

T039, accepted ADR-005, current Phase 3 services and repositories. T033 is resolved here: PlanStep is runtime-only and persistent TaskStep is deferred.

## Contract to freeze

Define typed serializable AgentState (`task_id`, `task_run_id`, sanitized task input snapshot, validated Plan, current position, execution result, verifier result, normalized failure, retry_count, replan_count, internal terminal outcome), graph topology, T035 lifecycle calls, internal runtime entry, one retry and one replan budgets, `taskpilot-run:<task_run_id>` checkpoint identity, resume/corruption rules, independent persistence/transaction ownership, stale-lock/concurrency tests, tenant trust boundary, side-effect-free scope, and deferred HITL/HTTP idempotency/worker scope.

The exact canonical field types, initialization, mutation rules, Plan,
PlanStep, ExecutionResult, VerificationResult, RuntimeFailure,
FailureClassification, routing table, budget semantics, trusted entry
signature, and resume/race invariants are frozen in ADR-006's “Canonical
runtime contracts” section. T041–T050 must implement those definitions
without inventing alternate shapes.

## Acceptance criteria

ADR-006 and this card are implementation-ready, every field and transition is explicit, Task/TaskRun enums are unchanged, and the canonical DAG T040–T051 has no ambiguity. Planning Strong Review approval is complete; T041 is the first executable implementation task.

The contract must mechanically terminate: one additional retry and one
replacement Plan maximum, counters monotonic and mutually non-resetting, and
all malformed-after-repair paths terminal.

### Exact AgentState summary

| Field | Type | Initial value | Mutation |
|---|---|---|---|
| `task_id` | UUID string | required | immutable |
| `task_run_id` | UUID string | required | immutable |
| `task_input` | `{title: non-empty string, max 255 chars; description: string \| null}` | sanitized snapshot | immutable |
| `plan` | `Plan \| null` | null | planner/replan only |
| `plan_position` | integer >= 0 | 0 | advance; reset only on accepted replacement Plan |
| `execution_result` | `ExecutionResult \| null` | null | executor; cleared on replan |
| `verification` | `VerificationResult \| null` | null | verifier; cleared on replan |
| `failure` | `RuntimeFailure \| null` | null | classifier; cleared on replan |
| `retry_count` | integer >= 0 | 0 | monotonic, one increment before retry |
| `replan_count` | integer >= 0 | 0 | monotonic, one increment before replan |
| `terminal_outcome` | `SUCCEEDED \| FAILED \| null` | null | set once; runtime-only |

All values are JSON/checkpoint serializable. No session, ORM, repository,
CurrentPrincipal, secret, role, organization authority, or checkpoint object
is permitted.

### Exact routing summary

`initial → planner → executor → verifier`; executor failure and verifier FAIL
go to classifier; verifier PASS calls T035 `succeed_run`; classifier RETRY
consumes the one retry then returns to executor; classifier REPLAN consumes the
one replan, replaces Plan/reset fields, then returns to planner; classifier
TERMINAL or either exhausted budget calls T035 `fail_run`; planner/verifier
invalid after one repair is terminal. This finite graph cannot cycle
indefinitely because neither counter resets the other.
