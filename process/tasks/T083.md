# T083 — Runtime approval boundary

Depends on: T082.

Integrate server-side risk classification immediately before a side-effect
boundary. For L2, atomically create/reuse the approval, persist a checkpoint
containing only bounded pending-approval data, and return WAITING_APPROVAL
without invoking the effect. L0/L1 retain current bounded behavior; L3 is
blocked. Preserve T035 lifecycle ownership, retry/replan budgets, tenant
validation, checkpoint identity, and terminal-state protection. Follow ADR-008
B2: commit create/reuse in business persistence before the independent checkpoint
write; a write failure executes nothing, and replay reuses the canonical row.
Checkpoint data never supplies a decision. Waiting is returned only after a
successful checkpoint write; reject resolves via T035 without overwriting a
terminal winner.

Evidence: approval-before-effect, checkpoint-before-wait, replay safety,
rejection/cancellation, malformed checkpoint, and concurrent resume tests.
