# T049 — Bounded replan

Depends on: T048. Implementation Model: STRONG/STANDARD; Review: Strong Review.

## Objective and scope

Implement exactly one replan budget and route selected verifier/classifier failures through a new validated Plan without resetting retry/replan counters or creating a new TaskRun. No infinite recovery, generic planner framework, or new status.

## Acceptance / security / transaction / tests

Tests cover replan success, replan exhaustion, counter monotonicity, and terminal routing. Replan output cannot grant tenant/role/tool authority. T035 owns lifecycle commits/rollbacks; no transaction spans runtime execution. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: runtime recovery/planner integration. Required tests cover bounded routing and counters; PostgreSQL evidence is required for durable lifecycle assertions where applicable. Strong Review is required.

## Frozen counter semantics

`REPLAN_BUDGET = 1`; `replan_count` starts at `0`. On REPLAN, if
`replan_count < 1`, increment to `1` before invoking the planner, accept a
new validated Plan, replace the old Plan, reset `plan_position` to `0`, and
clear `execution_result`, `verification`, and `failure`. Do not reset
`retry_count`. Otherwise route terminal failure. Replanning does not create a
new TaskRun, and planner repair does not consume this budget.
