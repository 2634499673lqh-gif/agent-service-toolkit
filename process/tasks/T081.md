# T081 — Approval persistence and migration

Depends on: accepted ADR-008/T080. Implementation follows existing SQLAlchemy,
Alembic, tenant-scoped repository, and service-owned transaction conventions.

Add only the approved tenant-scoped Approval table and constraints: immutable
sanitized proposed action, risk/status enums, run/actor foreign keys, requester
and decision actor, timestamps, deterministic action key, and indexes needed
for tenant/run/status lookup and duplicate-effect protection. No generic policy
tables or audit platform. ADR-008 B1 is the exact schema authority: ownership
is normalized through Approval -> TaskRun -> Task.organization_id (no duplicate
task/tenant columns); all lookups join that SQL path. Use RESTRICT run/membership
FKs, unique (task_run_id, replan_count, step_position), the listed CHECKs and
index, and AVAILABLE/COMPLETED/FAILED outcome columns on Approval itself.
Repositories query/flush; services commit/rollback, locking Task then Run then
Approval. Test invalid foreign keys, state/field combinations, and uniqueness.

Evidence: upgrade/rollback/coexistence migration checks, constraints, tenant
scoping, and transaction rollback tests.
