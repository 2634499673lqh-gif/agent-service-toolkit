# T045 — Verifier schema

Depends on: T044. Implementation Model: LOW_COST; Review: Strong Review.

## Objective and scope

Implement the minimal typed verifier output: `PASS` or `FAIL`, required criteria/evidence/reason fields only, and deterministic serialization. Evidence is explanatory data, never authorization truth. No generic evaluation platform or approval model.

## Acceptance / security / transaction / tests

Valid PASS/FAIL results parse; malformed verdicts and disallowed fields fail deterministically; evidence is sanitized and bounded. Add focused schema tests. No database transaction or API. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: verifier schema. Evidence is not authorization truth. Required tests are schema/serialization tests; PostgreSQL/integration evidence is not required. Strong Review is required.

## Frozen contract

`VerificationResult` is `{verdict: PASS | FAIL, reason: non-empty string <=
500 chars, evidence: list of <= 8 strings <= 500 chars}`. `evidence` may be
empty for either verdict; all values are sanitized. There is no criteria field.
Serialization is JSON-only.
