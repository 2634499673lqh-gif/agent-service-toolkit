# T047 — Failure classifier

Depends on: T046. Implementation Model: STANDARD; Review: Strong Review.

## Objective and scope

Define the small explicit classification contract needed to choose retry current execution, replan, or terminal failure. Normalize internal exceptions and keep sensitive details out of user-facing data. Do not create a universal taxonomy or new lifecycle states.

## Acceptance / security / transaction / tests

Table-driven tests cover every category and deterministic routing, including unknown/unsafe failures as terminal. Classifications are runtime data only and cannot grant authority. No database transaction is held. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: recovery classification. Sensitive exceptions remain internal. Required tests are table-driven unit tests; no PostgreSQL evidence is required. Strong Review is required.

## Frozen contract

`FailureClassification` is exactly `RETRY | REPLAN | TERMINAL`.
`RuntimeFailure` is `{classification, code <= 64 chars, sanitized_message <=
500 chars}` with sanitized strings and no raw traceback. Retryable deterministic execution failure maps
to RETRY; explicitly recoverable plan/verifier inadequacy maps to REPLAN;
unknown, unsafe, malformed-after-repair, policy-invalid, and unsupported
failures map to TERMINAL. This table is normative, not implementation choice.
