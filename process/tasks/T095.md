# T095 — Provider usage adapter

Depends on: T093. Review: Strong Review.

## Objective

Normalize provider usage honestly and keep unavailable values distinguishable
from zero.

## Required contract

Return either:

~~~
{"status":"known","input_tokens":123,"output_tokens":45,"total_tokens":168,"cached_input_tokens":0}
~~~

or:

~~~
{"status":"unavailable","reason":"not_returned"}
~~~

The unavailable reason is one of not_returned, unsupported, or malformed. All
token counts are integers in 0..1,000,000,000,000. A missing total may be
derived only from two valid input/output counts. Invalid, negative, partial, or
out-of-bound provider data becomes the unavailable shape; it is never changed
to zero. Persist and return that shape so the reason remains observable.
Provider metadata is limited to allowlisted provider/model/response identifiers
and 2,048 compact UTF-8 bytes.

## Acceptance and negative evidence

Table-driven tests cover known complete usage, derived total, unsupported
provider, missing fields, malformed types, negative values, bounds, and the
invariant that unavailable usage is never numeric zero.

## Documentation and checks

Update observability documentation and run focused tests, static checks, and
git diff --check during implementation.
