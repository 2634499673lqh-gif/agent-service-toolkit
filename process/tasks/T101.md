# T101 — Deterministic fixture set

**Model:** LOW_COST/STANDARD; **Review:** Strong Review; **Depends:** T100.

Implement the five provider-free fixtures from ADR-010. The first case is the repository-backed `deterministic.fixture_baseline`, not a tabular/sum capability. It must reuse the existing server-wired `DeterministicFixtureCapability` (`deterministic_fixture`) and return its exact bounded output `deterministic-read-only-fixture:v1` for the exact input, step, and expected evidence contract frozen in ADR-010. Add the retry-then-pass, replan-then-pass, L2 approval-required, and L3 blocked cases using existing runtime primitives. Freeze the required evidence codes from ADR-010: retry (`retry_observed`, `recovery_pass`), replan (`replan_observed`, `recovery_pass`), L2 (`approval_required`, `approval_satisfied`, `execution_succeeded`), and L3 (`blocked_before_execution`). Do not add production capabilities or persistence.

**Acceptance:** stable IDs and versions; exact bounded inputs/expected outputs; explicit required evidence; PASS/FAIL/ERROR behavior; prohibited payloads absent; total suite remains five cases.
