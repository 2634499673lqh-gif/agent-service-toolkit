# T082 — Approval service and decision APIs

Depends on: T081.

Implement create/read/approve/reject through service and minimal protected
endpoints. Derive organization and actor from CurrentPrincipal; owner/admin
only may decide. Enforce immutable proposal, one terminal decision, 404/403
ordering, stale/cancelled-run rejection, sanitized responses, and decision
audit fields. ADR-008 B2 freezes create/reuse by unique
(task_run_id, replan_count, step_position), immutable proposal equality, and
Task -> Run -> Approval locking within a service-owned transaction. Concurrent
creation reuses the committed row; mismatched proposals conflict. First decision
commit wins; all duplicate/competing decisions return 409, including identical
ones. Terminal/stale runs conflict without modifying approval evidence.

Evidence: same/cross-tenant authorization, member denial, forged IDs/roles,
duplicate/concurrent decisions, redaction, and transaction tests.
