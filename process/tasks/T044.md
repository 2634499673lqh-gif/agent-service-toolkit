# T044 — Deterministic execution path

Depends on: T043. Implementation Model: LOW_COST; Review: Strong Review.

## Objective and scope

Implement exactly one deterministic normal execution path through the executor using injected in-memory behavior. Include a controlled fail-once/always-fail test double for later recovery tests. No real provider, tool registry, shell/filesystem/network, TaskStep persistence, or external side effect.

## Acceptance / security / transaction / tests

Normal execution produces a stable result in AgentState; forced failures are normalized without exposing sensitive exceptions. Tests prove repeatability and no external calls. T035 remains the only Task/TaskRun status mutator. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: deterministic runtime execution. Tenant scope is validated before lifecycle calls. Required tests are deterministic unit tests; no PostgreSQL evidence is required. Strong Review is required.

## Frozen contract

The sole production path deterministically transforms the bounded
`PlanStep.instruction` and sanitized task input into a stable output string.
An injected fail-once/always-fail test double returns the exact failure-shaped
`ExecutionResult` from T043; it is not an external-effect abstraction. No
network, filesystem, shell, provider, credentials, or generic tool registry is
introduced.
