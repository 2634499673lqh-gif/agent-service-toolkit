# T091 — AgentRun persistence

Depends on: T090. Review: Strong Review.

## Objective

Persist one bounded, tenant-scoped observation for each server-selected
agent/node invocation.

## Required contract

Implement the AgentRun table exactly as specified in ADR-009:

- UUID id is the server-generated agent_run_id.
- task_run_id is the only ownership foreign key and uses ON DELETE RESTRICT;
  tenant ownership is task_run_id -> task_id -> organization_id.
- request_id is a nullable middleware UUID; replan_count, step_position
  (zero-based 0..7), and retry_count (0..1) are copied from validated runtime
  state.
- agent_name is a server-selected non-blank string of at most 128 characters.
- The observational status is one of running, succeeded, failed,
  waiting_approval, or unknown; it cannot drive TaskRun lifecycle.
- error_class, error_code, error_message, UTC timing, duration, usage,
  provider metadata, and row timestamps use ADR-009 bounds.
- Enforce UNIQUE(task_run_id, replan_count, step_position, retry_count,
  agent_name).

Do not add organization_id, a duplicate task_id, a TaskStep entity, raw
checkpoint/context/model data, or an independent tenant authority.

## Transaction and SQL requirements

Repositories flush only and never commit, roll back, close, or replace the
caller session. Inserts resolve the parent TaskRun in the trusted tenant scope.
Every read joins through Task and applies the principal organization predicate
in SQL. Parent deletion is restricted; no public trace delete is added.

## Acceptance and negative evidence

Migration up/down, PostgreSQL schema constraints, duplicate canonical identity,
cross-tenant read, foreign-parent rejection, timestamp/bounds, and rollback
tests are required. A failed trace write cannot leave a partial committed row.

## Documentation and checks

Update the database/observability docs and run focused tests, static checks, and
git diff --check during implementation.
