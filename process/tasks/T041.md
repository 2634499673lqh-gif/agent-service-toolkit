# T041 — Planner schema

Depends on: T040. Implementation Model: LOW_COST; Review: Strong Review.

## Objective and scope

Implement the minimal typed Plan and PlanStep runtime schemas frozen by T040, with structural validation and bounded invalid-output repair/fail behavior. PlanStep is not a TaskStep ORM/business record. No prompt framework, authority fields, persistence, API, or external side effect.

## Acceptance / security / transaction

Valid plans parse deterministically; missing, extra, malformed, and oversized fields fail or take the single documented bounded repair path. Planner data cannot select tenant, role, credentials, or tools. No database transaction is held. Add unit schema/serialization tests and update docs/progress; no PostgreSQL evidence unless schema serialization is covered by an existing fixture. No Codex commit/push.

## Governance

Affected layer: runtime schema. Strong Review is required. PostgreSQL/integration evidence is not required beyond existing fixtures.

## Frozen contract

`Plan` is `{steps: list[PlanStep]}` with 1–8 steps. `PlanStep` is
`{position: int, instruction: str}`. `position` is positive and must be the
exact ordered sequence `1..N`; duplicates, gaps, empty plans, extra fields,
and instructions longer than 500 characters are invalid. `instruction` must
be non-empty after sanitization. No permission, tenant, role, credential, or
tool-authority field exists. Serialization is JSON-only.
