# T022 — User model, email identity and password field

Implementation Model: STANDARD  
Review Model: STRONG_REVIEW_REQUIRED

Implement the approved User schema only. Do not implement login, token issuance, Membership, authorization dependencies, or public registration.

## Depends on

T020 and T021.

## Scope and frozen fields

Use T021 async session/repository boundaries. Add User with UUID4 `id`, trimmed display `email`, non-null globally unique `normalized_email`, and Argon2id-compatible `password_hash`, `is_active`, UTC `created_at`/`updated_at`, and explicit indexes/constraints. Use one canonical application helper: trim Unicode whitespace for display `email`, then Unicode `casefold` for `normalized_email`. Every bootstrap/login/controlled identity path uses it. Enforce database `NOT NULL` and global `UNIQUE(normalized_email)`; do not emulate Python casefold with PostgreSQL `lower()` or collation.

## Verification

Test duplicate normalized email, inactive state, UTC timestamps, serialization/log redaction, migration metadata, fresh/existing upgrade, LangGraph coexistence, rollback policy, and PostgreSQL-only schema. Hashes and credentials never appear in fixtures, responses, or logs.

## Forbidden

No password library or login behavior before T023. No public self-registration. Do not change `AUTH_SECRET` or upstream caller identity behavior.
