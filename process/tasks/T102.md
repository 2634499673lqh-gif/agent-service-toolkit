# T102 — Workflow Evaluation runner

**Model:** STANDARD; **Review:** Strong Review; **Depends:** T100, T101.

Implement one repeatable local Python/test execution boundary for the versioned suite. Run the five cases in canonical order, isolate case failures, return bounded typed results, and require no network, live model, SaaS, or database. Use the existing Planner/Executor/Verifier, capability/context, retry/replan, and approval boundaries. A suite/case contract mismatch is explicit `incomparable`; it does not become a metric failure.

**Acceptance:** reruns are deterministic; runner status is exactly `completed`, `partial`, or `error` with the ADR-010 semantics; case status, failure-code, ordering, bounds, and provider mocking are tested.
