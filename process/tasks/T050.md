# T050 — Checkpoint / resume

Depends on: T049. Implementation Model: STRONG; Review: Strong Review.

## Objective and scope

Bind LangGraph checkpoint/thread identity to a tenant-validated TaskRun (`taskpilot-run:<task_run_id>`) and implement safe resume. TaskPilot owns PostgreSQL `taskpilot` schema/migrations; LangGraph independently owns checkpoint/store tables. No distributed transaction, migration of LangGraph tables, worker, or new API.

## Acceptance / security / transaction / tests

PENDING starts through T035 begin_run; RUNNING resumes the same checkpoint; terminal runs cannot resume; missing/corrupt checkpoint fails closed through T035 fail_run. Checkpoint data never selects organization/user/membership/role. PostgreSQL/LangGraph integration tests use fresh independent sessions and cover concurrent/repeated resume, cancellation race, stale identity, and final rereads. Update docs/progress; no Codex commit/push.

## Governance

Affected layer: LangGraph adapter plus runtime service. Tenant scope is supplied by trusted TaskPilot lookup, never checkpoint data. Transaction ownership remains split and non-distributed. PostgreSQL/integration evidence is mandatory. Strong Review is required.

## Frozen runtime and race contract

The internal boundary is
`TaskRuntimeService.execute_run(session: AsyncSession, *, organization_id:
UUID, task_id: UUID, task_run_id: UUID) -> RuntimeExecutionResult`. The trusted
caller supplies `organization_id`; it is never read from AgentState/checkpoint
or model output. Runtime validates Task and nested TaskRun in tenant-scoped
SQL before deriving `taskpilot-run:<task_run_id>`.

PENDING with no checkpoint starts through T035 `begin_run`; RUNNING with a
valid checkpoint resumes; terminal runs raise a stable runtime conflict and do
not resume; RUNNING with missing/corrupt checkpoint attempts T035 `fail_run`
and preserves any state that wins a race. Concurrent same-run resumes may
duplicate deterministic graph work, but only one T035 terminal transition may
commit and later completion cannot overwrite it. Repeated resume uses the
latest valid checkpoint. Cancellation winning preserves CANCELLED; terminal
completion winning causes later cancellation to follow T035 terminal rules.
No exactly-once node execution, lease, distributed lock, or live interruption
is claimed.
