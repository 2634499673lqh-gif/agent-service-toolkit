# T023 — Opaque authentication session/token service

Implementation Model: STANDARD  
Review Model: STRONG_REVIEW_REQUIRED

Implement login and credential issuance using ADR-004 opaque server-side sessions. Do not implement general authorization dependencies or change shared bearer compatibility.

## Depends on

T021, T022, and T022A.

## Scope

Add approved `pwdlib[argon2]` only after review. Use Argon2id verification, generic login failure, opaque token from at least 32 random bytes, SHA-256 hash-at-rest with indexed lookup, UUID4 session ID, 24-hour expiry, explicit revocation, and expired-session cleanup. Bind a session to user + membership; revalidate active state on every request. Add the controlled CLI/setup bootstrap contract: hidden interactive password prompt twice via `getpass`-equivalent, reject `--password` and positional plaintext password, and never log password/hash. First bootstrap creates Organization + User + owner Membership in one business transaction. Exact complete active owner state is an already-initialized no-op without duplicate rows or password reset. Partial/conflicting/inactive/mismatched state fails closed, non-zero, and never repairs, overwrites, changes password, or elevates role. No global consumed flag; no HTTP registration.

## Verification

Test valid/wrong/unknown/inactive login, generic errors, expiry, revocation, tampering/replay, hash/token redaction, hidden prompt use, rejection of plaintext CLI arguments, successful bootstrap, exact repeated no-op (no duplicate/no password reset), partial/conflicting fail-closed behavior, intermediate-failure full rollback, and plaintext/hash absence from logs. Full pytest is required at the authentication gate.

## Forbidden

No JWT, role claims as authority, refresh-token family, SSO, email verification/change, or `AUTH_SECRET` behavior change. `/api/v1` does not accept legacy bearer as a TaskPilot principal.
