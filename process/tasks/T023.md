# T023 — Authentication service

Implementation Model: STANDARD  
Review Model: STRONG_REVIEW_REQUIRED

Implement login and credential issuance using only the mechanism approved by T020. Do not add authorization dependencies or change upstream shared bearer compatibility.

## Depends on

T021 and T022.

## Acceptance

- Valid identity succeeds; wrong password, unknown identity and inactive identity return the approved generic failure.
- Expiration, revocation/invalidation, key management and required claims/storage follow T020.
- Passwords are securely hashed/compared; plaintext, hashes, credentials and tokens are absent from logs and response bodies except the intentionally returned credential.
- No anonymous registration; bootstrap uses the approved controlled path.
- Unit tests mock external providers and cover credential tampering and replay/expiry.

Full pytest is required at the authentication gate. Protocol, key, claims, expiration, revocation, and legacy AUTH_SECRET compatibility are frozen by T020.
