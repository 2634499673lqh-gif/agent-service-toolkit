# ADR-015 — Durable TaskRun worker and recovery contract

Date: 2026-11-07  
Status: Implementation baseline; independent Strong Review pending.

## Decision

TaskPilot uses the existing PostgreSQL `task_runs` table as a durable work queue.
The API commits a `PENDING` run and returns; a process-local worker polls the
database and claims work with `FOR UPDATE SKIP LOCKED`. The worker is durable
through persisted TaskRun state, not through an in-memory queue. A new service
process can reclaim an expired lease and resume from the latest LangGraph
checkpoint.

Each active run has a bounded worker lease (`worker_id` and
`worker_lease_expires_at`) and a persisted `worker_attempts` counter. The worker
renews its lease at a bounded interval. A stale `PENDING` or `RUNNING` run may
be claimed by another worker. Pending human approvals are excluded from polling
until the approval row is terminal; the next poll then resumes the exact run.

Worker execution is at-least-once. A crash can leave duplicate graph work after
lease expiry, so existing TaskRun identity checks and terminal lifecycle locks
remain authoritative. No exactly-once external effect or distributed lock is
claimed. The current capabilities remain deterministic/read-only or the existing
approved mock action; real destructive effects remain out of scope.

Worker exceptions receive a finite attempt budget. Before the budget is
exhausted the lease is released and the run remains recoverable. After the
budget is exhausted the run fails closed with bounded terminal metadata. A
missing checkpoint on a stale `RUNNING` row remains fail-closed rather than
replaying an unknown side effect.

The worker is enabled explicitly for the PostgreSQL Compose deployment through
`TASKPILOT_WORKER_ENABLED=true`. Local SQLite and legacy test paths retain the
existing process-local dispatch fallback until they opt into PostgreSQL worker
mode. No Redis, Kafka, queue service, or new public runtime endpoint is added.

## Acceptance boundary

- one concurrent claim per run under independent PostgreSQL sessions;
- lease renewal and stale-lease reclaim;
- restart recovery from a persisted checkpoint;
- pending approval exclusion and post-decision resume;
- bounded worker exception retry and terminal exhaustion;
- cancellation/terminal winner remains authoritative;
- tenant predicates and secret redaction remain unchanged;
- Compose migration and browser flow run with the worker enabled.

## Deferred

Autoscaling, cross-region failover, off-host queue storage, exactly-once
provider effects, arbitrary external side effects, and load-testing infrastructure
remain deferred.
